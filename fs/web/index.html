fs 0.4.0

Semantic search powered by embeddinggemma-2, automatically managed through Ollama or fs's built-in ONNX CPU runtime. Full-text search and metadata backed by SQLite. A persistent vector index, stored with your application data.

Developed by Chris Visser
github.com/vcsoc/fs ↗

Content extraction supports UTF-8 text, source code, PDF, and DOCX. Scanned PDFs require external OCR. The first semantic query can take longer while the model loads; warm searches reuse the in-memory vector matrix. No automatic filesystem watching: refresh your locations to update the index.

Scanning & analysis

Applied to the next indexing job. Changes do not interrupt a running scan.

Indexing runs asynchronously in a separate low-priority process. Linux disk I/O runs at idle priority. The UI remains independent of the worker. All parallel file threads share one model instance and memory ceiling; pending work is bounded. Direct inference and decoder helpers count towards the aggregate indexing budget. It does not include the search service's model cache or a separately running Ollama service; their total memory and GPU memory are not hard-capped here. CPU-only inference is the default.

LOCAL MODEL SETUP

How should fs run your model?

Ollama is not installed. May fs download and install a private Ollama runtime and set up embeddinggemma-2?

No administrator access or system PATH changes are needed. Ollama downloads vary by platform, plus its model download. If you say no, fs downloads the selected supported EmbeddingGemma 2 ONNX export (about 505 MB for the full 740M model) and runs it directly, locally, on your CPU. No substitute model is used.
